# Zakres SlavicGame 1.0 — v0.1

## Format gry

- single-player;
- third-person;
- Adventure RPG / Action RPG;
- duże regiony zamiast jednego seamless kontynentu;
- kampania fabularna + side questy;
- offline jako podstawowy model.

## Core 1.0

Musi istnieć:
- eksploracja;
- melee;
- łuk;
- tropienie;
- dialog;
- questy;
- inventory/equipment;
- alchemia;
- rytuały;
- podstawowe czary;
- reputacja;
- boskie umowy;
- dzień/noc;
- pogoda;
- save/load;
- pięć ending architectures;
- epilogi.

## Regiony

Docelowy obraz:
- R0 Pogranicze Żarnowca;
- R1 Nadborze;
- R2 Wielki Bór;
- R3 Przymorze;
- R4 Kamienne Wyżyny;
- R5 Równiny Arel;
- R6 Pustkowie Pierwszego Progu;
- sekwencje Nawii.

Jeśli produkcja wymaga cięcia:
- łączy się funkcje regionów;
- nie wycina się kluczowych prawd kampanii.

## Open world

**Nie** w sensie jednej gigantycznej mapy.

Gra jest:
- regionalnie otwarta;
- eksploracyjna;
- z powrotami.

## Multiplayer

Nie jest częścią bazowego 1.0.

Silnik nie musi być projektowany pod MMO/co-op kosztem single-player.

## Companion party

Brak stałej 4-osobowej drużyny jako core feature.

Możliwe:
- quest companions;
- czasowi sojusznicy;
- wspólne wyprawy.

Nie budujemy pełnego party-RPG, jeśli kampania działa bez tego.

## Romance

Nie jest wymaganym filarem.

Może pojawić się później tylko dla konkretnych postaci i jeśli nie wymusza przebudowy głównej produkcji.

## Survival

Brak:
- obowiązkowego głodu co kilka minut;
- pragnienia jako stałego licznika;
- snu wymuszanego timerem.

Jedzenie, odpoczynek i przygotowanie mają funkcję RPG, nie survival micromanagement.

## Building

Brak pełnego:
- city buildera;
- base buildera;
- własnej wioski od zera.

Możliwe:
- naprawy;
- rozwój usługi;
- zmiana stanu miejsca przez quest.

## Mounts

Nie są wymagane dla vertical slice.

Dla makroregionów:
- mogą istnieć jako podróż/transport;
- finalna mechanika mountów zależy od wielkości regionów.

Nie projektujemy map sztucznie dużych tylko po to, by potrzebować konia.

## Procedural generation

Nie jest podstawą questów ani świata.

Proceduralnie można wspierać:
- dekorację;
- drobne ambienty;
- techniczne rozmieszczenie.

Główna treść jest projektowana ręcznie.

## Level scaling

Brak pełnego rubber-band scaling całego świata.

Preferowane:
- zakresy trudności;
- warianty przeciwników;
- przygotowanie;
- czytelne strefy ryzyka.

Gracz może wrócić silniejszy.

## Loot

Brak modelu:
- setki mieczy +2 z losowym kolorem rzadkości.

Sprzęt ma:
- funkcję;
- pochodzenie;
- różnice stylu gry.

## Monetization

Dokumentacja designu zakłada pełną grę premium.

Nie projektujemy systemów gameplay pod:
- loot box;
- energy timer;
- pay-to-win.

Model wydawniczy może zostać ustalony później, ale nie może wymagać przebudowy core loop.

## Android

Android jest platformą późniejszą.

PC jest platformą referencyjną pierwszej pełnej wersji.

## Najważniejsza granica

Jeśli nowy feature nie wzmacnia:
- zawodu łowcy;
- żyjącego świata;
- niepewnej wiedzy;
- przygotowania;
- decyzji i konsekwencji

to musi uzasadnić koszt produkcji.
